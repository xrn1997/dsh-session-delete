# 回收站面板跨挂载先画上一份成功读数

Status: accepted

回收站面板是宿主 `main` 的 keyed 占用者，切到别的页面就整棵卸载；状态只活在组件里，每次回来都要从「正在读回收站…」重画两栏。决定把上一次成功读到的清单、选中与详情留在模块级，面板挂载首帧先画它，再静默重读。

## 背景

宿主对同一类问题的做法不是加动画，而是「面板卸载、状态不丢」：插件管理页把 controller 与 slot store 放在组件之外，目录选择器让旧视图继续渲染到新数据落地。回收站面板原先把清单、选中与详情全放在组件状态里，于是宿主一切页面就丢现场；回来时首帧 `loading`、清单落地后再自动选中、详情再进一次骨架，百来毫秒里版面轮换三次。用户要的是「切换不闪」，不是更短的闪。

首帧快照不是「清单状态」的第四态：三态仍然只描述**此刻读没读到**；快照只是挂载首帧的起点，重读一落地就退场。它也不是持久化：进程重启即无，回收站的事实永远只问宿主。

## 决定

1. **快照内容 = 上一次成功的清单、选中与详情账本。** 模块级、挂载读一次、不订阅、不持久化。折叠集、列宽与孩子视图不进快照：它们是视图状态，跨挂载记住会与 `docs/ui-spec.md` 的既有口径打架。
2. **刷新中不是第四态。** 清单三态不变；另交 `refreshing`，只表示「清单已有行、重读还在飞」。行可能来自首帧快照或上一次成功读数。视图只拿它挂 `aria-busy`，不画「更新中」字样。
3. **重读失败整份丢掉。** 快照与详情账本一起作废，清单落 `unknown`；旧行不许继续冒充此刻的回收站。成功读数按上一份清单修剪：选中行不在了就置空，顶部条目详情不在了就删；孩子详情从不在清单行里，保留。
4. **写动作成功丢对应详情。** 恢复或彻底删除后，该条详情不再属于回收站；即使随后清单重读失败，也不许从旧账本里再画出来。

## 边界

- 不跨进程、不重启续命，也不写盘：回收站的事实源只有宿主。
- 快照只由**当前挂载**的读数写回：卸载后晚到的响应属于上一次界面，成功与失败一律不落快照（否则旧读数会盖掉新挂载刚写下的行，还会按旧行剪掉仍在的详情）。
- 详情账本常驻有上限（按最近一次写入淘汰）：孩子详情不随清单修剪，但没有上限时打开几十个子会话就会把每份详情留在进程里。
- 不改 Node 半，不改清单三态与 `/list` 契约。
- `unknown` 照旧不向下游交行；刷新期间旧行可操作，但写路径自己复核（恢复的 already-gone、彻底删除的 live recheck）。
- 换条目如何保持上一帧、切换如何稳住几何、如何减少冷读，分别归 ADR-0049、ADR-0050、ADR-0051。
- 上限淘汰掉**当前正显示的那一条**时，读路把它当成「没读过」补一次读（否则详情只剩一个没有请求在飞的骨架，读者要再点一次这一行才回来）。淘汰不看谁在屏上：那是读路的收口，不是账本要多记一份「谁在用」。

## 被否方案

- **每次挂载都从 `loading` 画**：等于接受每次切页面都闪一次；宿主自己的面板已有「状态在组件外」的先例。
- **把折叠集、列宽、孩子视图也存进快照**：这些是视图状态，跨会话记住会在下一次挂载时把布局带回一个用户没要求的状态。
- **把快照持久化到磁盘**：会造出第二份「回收站现在长什么样」的事实，且与宿主账本的一致性无从保证。

锚点：`src/client/trash-snapshot.ts` 的 `readTrashSnapshot` / `reloadSucceeded` / `noteSelection`（符号已收成意图名，本篇的可观察规则原文不变）；`src/client/use-trash-query.ts` 的 `listView` 与 `TrashQuery.refreshing`；`src/client/use-trash-panel-controller.ts` 的 `detail`；`docs/ui-spec.md` §3；`CONTEXT.md` 的「清单状态」「首帧快照」「详情账本」；`tests/client/trash-snapshot.test.ts`；`tests/client/use-trash-query.test.tsx`；`tests/client/trash-panel.test.tsx` 的「切换稳定性」。相关 ADR-0049、ADR-0051。
