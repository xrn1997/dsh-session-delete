# 悬停或聚焦 150ms 后再预取详情

Status: accepted

点击一条未读条目才读详情，会让详情保持替所有冷读兜底；但鼠标扫过整列就发请求又会变成一串 `/detail`。决定清单行与子会话行在 hover / focus 停留 150ms 后预取该条详情：只热身账本，不改选中、不占详情上屏槽、不露 loading。

## 背景

本机一次详情读数通常在百来毫秒量级。预取的意义是让点击落在账本命中上，把保持期从「通常」变成「几乎总是」；它救不了键盘慢触发、触屏与冷读，所以仍要与 ADR-0049 的保持叠加，而不是替代它。150ms 是「扫过」与「停下来看」的分界：短到点下去之前通常已经读完，长到连续划过只发最后一次。

预取与选中是两条读路：选中要决定「现在画谁」，预取只决定「账本里有没有」。把预取接进选中的上屏路径，会在用户正在保持 A 时把详情上屏槽摆到 C，画面立刻塌回骨架——这正是预取要消灭的那一帧。所以预取只允许碰账本与在飞登记。

## 决定

1. **意图 = hover 或键盘 focus。** 两者停留 150ms 后触发，提前移开或卸载取消；连续划过只认最后一次。鼠标与键盘得到同一份行为，不把键盘用户漏掉。
2. **预取只热身账本。** 不改选中、不触发下钻、不占用详情上屏槽、不清失败态、不把当前主体打成 loading；成功写账本与首帧快照，失败不记账本，也不污染当前正在画的详情。
3. **与选中共用一条读路与在飞去重。** 同一条已在飞时，选中不会发第二条请求：预取的响应落地后，选中该条直接命中账本；选中途中的失败仍落该条自己的失败块，不会卡成永久 loading。
4. **子会话行同一套行为。** 父详情里的子会话行在可点击时同样预取；孩子视图里入口不交出，预取自然不发生。

## 边界

- 不预取相邻行、不预取全部可见行：意图预取只看指针/焦点落在哪一条。
- 不改 Node 半、不新增依赖；预取与选中共享同一条 `/detail` 契约。
- 保持与骨架的判据归 ADR-0049；几何归 ADR-0050。

## 被否方案

- **不做预取**：键盘慢触发、触屏与冷读仍要走保持期，点击后的等待没有减少。
- **渲染时就预取**：一屏十几行会变成一串请求，且大多不是用户意图。
- **把延时调长到接近点击**：省了请求，但点下去时还没读完；150ms 是本机读数与「扫过」的交点。
- **复用选中的上屏路径做预取**：会抢占详情上屏槽，把保持中的上一条顶成骨架。
