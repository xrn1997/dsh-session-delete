# 详情的分页按钮为什么换成右缘的提问轨

Status: superseded by 0057

详情右缘常驻一道提问轨：一句用户提问一格，悬停出预览、点一下跳到那句。正文工具栏的「加载更早」整颗拿掉，连续往前读改成滚到顶自动补一页；分页仍是按块游标，跳得远的那句靠游标循环补页到它进窗。

## 背景

ADR-0047 把四档工作步骤与「简洁档联动分页」一起做进来时，前提是：一页全是被藏起来的过程块时，点「加载更早」看着没反应，所以要自动连翻；标准及以上每页至少有一行可见内容（过程组头），保持一次点击一页。真机上这个前提站不住：过程组头是**折叠**的，一页工具调用在标准档里就是一行「工作步骤 · N 步」；而 prepend 后的滚动补偿会把新翻进来的这一页顶到视口上方——读者点一下，画面几乎不动，只能反复点。长会话里「翻到某一句」于是退化成几十次盲点。

宿主 `ui-chat` 的回答是轮次轨：贴右缘常驻、一轮一格、悬停预览、点一下跳；未加载的轮次走 `loadThrough`，实现是从尾往前循环取页直到窗口覆盖目标。那道轨最要紧的性质是**零开合**：读者从头到尾只做一个动作——点要去的那一格。

## 决定

1. **提问轨取代分页按钮。** 右缘常驻、30px 宽、一句提问一格（10px 一节），不占正文布局，正文留 44px 右槽。悬停 / 键盘聚焦出预览卡（序号、时间、80 字预览、要不要补页），点一下跳。零开合：不做折叠目录、不做弹层、不做常驻左栏（三案都在评审里被否，见下）。
2. **跳转是补页循环，不是一次请求。** 目标在已加载窗口里就直接滚过去；不在就按 `olderCursor` 一页页补，直到它进窗。补页期间每落一页按高度差把读者按在原处；落位只把那句对齐到 sticky 标题排之下，**不画落地高亮框**——宿主的 `scrollToTurn` 也只做对齐，读者靠滚动位置与轨上那格的 `aria-current` 认落点。上限 `JUMP_PAGE_LIMIT` 页；超限只留一句「这句离现在太远，先点更近的一条」，不静默卡住；读失败就停在那一页（失败原文仍走详情的分页失败面）。
3. **连续阅读改成滚到顶自动补一页。** 手动按钮拿掉后，正文**从下方滚回**离顶 24px 内触发一次补页（保留原有滚动锚点，读者不被拽走）；首挂与程序性回顶都不触发——挂载那一刻 `scrollTop` 本来就是 0，换条目时复位到 0 的那一拍也不是读者在要更早的页，拿 scroll 事件本身当判据会替每次切换多补一页。
4. **整条会话的提问索引随首次 `/detail` 过线。** 每条提问给块序号、时间与 80 字预览；它不随分页变化，带 `before` 的后续页不重复搬。服务端本来就在流整条日志算计数与页，几乎零额外成本。`id` 就是块序号（与 `blocks[].id` 同一套），跳转与「当前哪句」都拿它对齐。
5. **四档工作步骤不变。** 简洁 / 标准 / 详细 / 完全展开、默认标准、完全展开是一次性默认、过程组的键取组后那条对话——这些仍按 `docs/ui-spec.md` ⑥ 执行。本篇只推翻 ADR-0047 的分页联动两条（分页按钮、标准以上一次一页、点击后自动连翻的触发源）；简洁档的自动连翻保留，触发源从「点按钮」换成「补回来的一页全是过程块」，判据与上限不变。

## 边界

- **不做虚拟滚动**：正文仍是全量 DOM；跳远那句的代价是补页请求与渲染，不是视口窗口化。真要做窗口化是另一篇。
- **不做「按提问替换正文窗口」**：那会在两次跳转之间留洞——两段之间没加载的块没有入口，与「删前看全」冲突。
- **索引不分页**：它随首次读一次过线，条数随会话增长、预览有界。宿主把同类读数做成投影并从 summary 里排除；本插件没有投影面，挂在详情首读上是等价的省法。
- **轨不跨会话记状态**：当前哪句、补页现场只活在当前这条详情里，换条目重挂载即清。
- **段名表不动**：没有新通道；`/detail` 只多一格可选字段（形状仍归 `src/shared/wire.ts`，ADR-0003）。

## 后果

- 服务端 `src/trash/detail.ts` 在流日志时顺手产出 `prompts`；`PageBuilder.add` 改为回块序号（页内页外都给）。线上形状多 `TrashDetailPromptWire`。
- 客户端多 `src/client/prompt-rail.tsx`（画）与 `src/client/use-prompt-rail.ts`（当前哪句、补页、落位）；`src/client/use-detail-pager.ts` 多「滚到顶自动补页」；`src/client/trash-panel.tsx` 多一层 `DETAIL_PANE` 包住滚动容器与轨。
- 「加载更早」按钮与它的两句 copy 删除；`detail.compact.pageOnly` 改成「往上滚继续往前看」。
- 窄档正文少 44px（给轨让位）；提问 100+ 时刻度密到 10px 一节、轨内自己滚。

## 被否掉的替代

- **折叠目录条 / 常驻左栏 / 工具栏弹层**：三案都做过真比例 mockup。前两案要读者先开、先找、再关，或永久让出正文宽度；弹层还会盖住正文。共同毛病是把导航变成一件要管理的控件，而不是「点一下就到」。
- **保留「加载更早」按钮，另加一道轨（宿主那样）**：宿主的正文是虚拟化窗口，按钮是唯一的连续加载入口；我们的按钮已经被证明看不见效果（折叠组头 + 滚动补偿），留着只会继续误导。
- **按提问一次取一大段**：正文没有虚拟化，一次把几百块塞进 DOM 比逐页补更慢，也更占内存。
- **把轨做进滚动容器（sticky）**：sticky 在滚动容器里贴不到视口中线，滚到中段就跟着走。
- **落位时给目标行套一圈高亮**：user 行整行大半是空白，一圈环在正文里就是一个大白框；宿主也只对齐、不画。
