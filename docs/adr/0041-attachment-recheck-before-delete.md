# ADR-0041 — 附件计划在执行期复核：删对象之前重扫剩余引用

Status: accepted

附件独占判定发生在计划期，而真正删对象在几十次目录删除之后；这中间另一个会话可能把同一张图（内容寻址 ⇒ 同一个 `sha256` id）再引用一次，或派生存储新写一条引用。计划是数据、会过期。执行器现在在删对象之前、目录已经删掉之后，用同一套剩余引用扫描再判一次，只删这一刻仍无引用的对象。

## 背景

ADR-0020 的独占计划要回答的是「这个图片副本除了被删的这些会话，还有没有别人在用」。它读被删会话的日志与全部剩余引用源，一次算完；ADR-0027 又把活体准入在执行器首笔写前重查了一次，因为计划与写之间隔着附件扫描。但活体查了、引用没查：窗口里一个新引用产生，计划里那个对象仍然会被删掉，活体会话里的图片随即变坏，而且没有回滚——对象已经被删。

窗口不是理论值：计划之后要先删完这一组的每个会话目录（逐条 `removeDir`），才轮到附件对象；大组上是秒级。内容寻址让「同一张图再贴一次」不需要重传字节，只要一次粘贴。派生存储（`storages` / `cache` 里带 `sha256:` 的 JSON）也可能在窗口里被宿主写一条新引用。

## 决定

1. 新增执行期复核 `recheckImageRemovalExclusivity`：入参是计划里的附件条目，重扫「全部会话日志 + 全部 `session-trash` 目录 + `storages` / `cache` JSON」，把这一刻已有引用的条目从计划里剔除，字节按剩余条目重算。
2. 调用时机在**会话 / 回收站目录已经删掉之后**、`executeImageAttachmentRemoval` 之前：那时被删的引用源已经不在，扫到的就是真正的剩余；保留「对象只在会话真的没了之后才动」这条既有顺序。
3. 读不出照旧 fail closed：回空计划 + `skipped`，宁可在盘上留下孤儿，也不删共享。空计划直接返回，不为零删付一次全 home 扫描。
4. 计划的原 `skipped`（候选日志读不出）原样保留；执行期复核不另造第二套跳过原因。

## 边界

- 不是原子性：重扫本身也有窗口，只是从「几十次目录删除」缩到「一次扫描」。要真正原子得宿主提供锁，这里没有。
- 不复核**候选侧**：被删会话日志在被删目录里，目录已经没了；候选集仍是计划期读到的那份。
- 不改计划、不改 `/list` 的 `releaseBytes` 与 `/detail` 的读数：那些仍是计划期口径；被执行期剔除的对象不会出现在成功回执的 `attachments.removed` 里。
- 不清理 `file-objects` / `tmp` / `v2` / `cache`，也不改 `maxJsonRefBytes` 上限（ADR-0020、ADR-0037）。

## 后果

- 有附件要删的永久删除多一次全 home 引用扫描（只读；无附件可删时零成本）。这是用一次读换「删掉仍被引用对象」的窗口。
- 回执的 `attachments.removed` 可能小于计划条目数；`freedBytes`（会话目录）不变，因为附件字节本来就不进它。
- 复核时读不出会返回 `skipped`，面板与维护卡的「跳过」半句照既有路径上屏；对象留在盘上，等下一次手动检查。
- 测试钉住：计划后新增引用被剔除、复核读不出整体跳过、空计划不扫描、执行器在删目录之后才复核。

## 被否掉的替代

- **计划完就删对象（原样）**：窗口最大，正是本篇要收的洞。
- **每删一个对象前查一次引用**：对象数可能很多，逐对象全 home 扫描比一次复核更贵；且一次扫描已经覆盖这一批。
- **把附件删除提到删目录之前**：那时被删会话自己的引用还在，会把候选全判成共享；而且对象先没了、目录删一半失败，恢复回来的会话图片就坏了。
- **不做，接受这个窗口**：后果是删掉仍被引用的活体图片，且不可回滚；与 ADR-0020「宁可留孤儿也不删共享」正面冲突。
