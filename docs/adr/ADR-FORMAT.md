# ADR 规范

ADR 只记三类同时成立的决定的 why：**难逆**、**无上下文会让人惊讶**、**当初真有过替代方案**。容易回退的不写；不令人惊讶的不写；没有真实替代方案的不写。当前结构、语义归属与读数不进 ADR：它们分别住 `docs/architecture.md`、`docs/ui-spec.md`、测试与代码。

## 文件与编号

- 放在 `docs/adr/`，命名 `NNNN-slug.md`（顺序编号 + 短横线小写 slug）。
- 编号扫现有最大号 +1，不复用、不跳号；只追加、别重排。
- 一篇只回答一个决定。一个决定需要多处改动，仍只写一篇；两个决定互相牵连但可分开翻案时，写两篇并互链。
- 每篇必须在 `docs/adr/README.md` 恰好出现一次；文档门核对索引与文件的一一对应。

## 结构

每篇至少要有：

```md
# 决策式标题

Status: accepted

导语 1–3 句：背景一句 + 决定一句 + 理由半句。
```

标题可以是 `# ADR-NNNN — 决策式标题`，也可以直接写决策式标题；读完标题就要知道结论。`Status` 只允许两种形态：

- `Status: accepted`
- `Status: superseded by NNNN`

`Status` 行不带日期、括号或补充说明；日期留在 git，补充说明写进正文。每篇末尾必须有 `锚点：` 一行。

决策重一分，多加一件；章节名允许近义，同一篇内保持一致：

| 章节 | 什么时候加 |
| --- | --- |
| `## 背景` / `## 动机` | 「为什么」一句话装不下：多股作用力、要澄清的误报、历史包袱。讲当时为什么变，用过去时。 |
| `## 决定` | 决定多于一件互相牵连的事，或单条决定需要分条展开约束。编号条目，每条自带理由。 |
| `## 边界` | 明确不做什么、哪些语义仍归别的家，防止下一步改错地方。 |
| `## 后果` | 改动横跨多模块/多文件，读者需要知道波及面；用现在时描述落地后的现状。 |
| `## 被否方案` / `## 被否掉的替代` | 拒绝本身需要论证、不记会被重提时。逐条给理由。 |
| `## 代价` / `## 权衡` | 接受这个决定要付出什么，以及为什么仍值得。 |

轻决策允许只有标题、导语、被否方案与 `锚点：`。专项章节按需命名（例如「行为差异」「客户端主视图」），不要为了凑章节写空段。

`锚点：` 的判据是**读者下一步能打开什么**：实现符号、钉住它的测试、`docs/ui-spec.md` 的章节、或其他 ADR 篇号。不写行号；不指已出库的过程产物；不拿 `.qoder/repowiki/` 当证据。`tests/docs.test.ts` 会把守标题、`Status`、`锚点：` 与索引。

## 互引与取代

- 互引允许，用相对链接或 `ADR-NNNN-slug` 指路；但开篇第一段必须自足，别把别篇正文抄过来当前情。
- 不引用仓外 ADR 编号：编号序列不对齐；溯源用提交 hash 或本仓可验证的锚点。
- 整篇不再成立：新写一篇，旧篇改为 `Status: superseded by NNNN`，正文保留；索引保留旧行并按需标「（已被 NNNN 取代）」。
- 只翻其中一条：属事实漂移（文件改名、符号搬家、路径变化）就就地改正文；属决定反转就按整篇取代处理，不写「后来又改回……」的补丁串。
- 每篇 ADR 写完后做一次取代检查：搜索现有篇目，若有同一决定，更新或取代旧篇，不新建第二份。

## 写作纪律

- 当前真相只写现在时；背景里讲「当时为什么变」才用过去时。不写日期、批次号、施工步骤或验收清单。
- 不抄会腐烂的读数与计数：构建产物大小、文件数、测试数都不进 ADR；要证据就指测试或代码。
- 点名仓内路径必须真实存在；改名或删除时同步改这里，或改指还活着的家。
- 引用历史写日期或 commit，别写批次号；读者手上没有能查的批次坐标。
- 代码与测试是最终真相；ADR 与代码冲突时改 ADR，并把长期成立的结论提炼回这里，而不是留在过程文档里。
