# ADR-0047 — 详情的工作步骤为什么抄宿主四档、简洁档为什么联动分页

Status: superseded by 0054

回收站详情要服务“删之前看全”，但长会话的正文里过程块（思考、工具、注入、系统消息、压缩摘要）常比对话多得多：原先只有「全部展开 / 全部折叠」一颗开关，读者要么在一屏几十条折叠头里逐条点，要么一次全铺开被工具输出淹没。决定把详情的过程块呈现改成宿主「工作步骤展示」同款的四档（简洁 / 标准 / 详细 / 完全展开），并让简洁档的「加载更早」按同一份预算自动连翻，直到这一页出现对话内容、翻完或到达上限。

## 背景

详情按块投影全部对话内容（ADR-0026），分页游标从页首往更早翻。过程块默认折叠本身是对的：删前核对时，用户提问与助手回答是主干，工具输出是证据。但“默认折叠”只解决了单块的长短，没解决**一页里过程块的数量**——一条工具密集的会话，一页可能全是折叠头，主干被推得很远。宿主 Chat 已经用「工作步骤展示」回答过同一个问题（简洁 / 标准 / 详细 / 完全展开），回收站的读者也熟悉那套语义；自己另发明一套筛选或密度开关，只会让同一份内容长出第二种读法。

## 决定

1. **四档是同一份块数据的四种投影，不是四份渲染器**：简洁只画用户与助手块；标准把**连续**过程块收成一行「工作步骤」+「N 步」，点开仍逐条折叠；详细逐条列出过程块、各自折叠；完全展开 = 详细档 + 一次性铺开当前页全部过程块。档位只决定“画哪些、默认开哪些”，块内容与附件渲染只有一套。
2. **默认「标准」**：对话是主干、过程是证据，恰好对应删前审阅的默认姿势。默认「简洁」会把工具证据藏到读者不知道要去找；默认「详细」会把主干推远。
3. **「完全展开」是一次性默认，不是锁**：切进这一档时铺开当前页所有过程块，之后仍可逐条收起；离开这一档收回。否则“完全展开”会变成第二个粘性状态，和“逐条折叠”互相打架。
4. **简洁档的「加载更早」联动分页**：服务端按块翻页，简洁档把过程块整段藏起来 ⇒ 一页可能全是被隐藏的块，点一下什么都不出现。简洁档下自动继续往前翻，直到这一批里出现对话块、游标耗尽或到达 `AUTO_OLDER_PAGE_LIMIT`。上限防的是“一条几乎全是工具调用的巨型会话”把一次点击变成几十个串行请求；标准及以上每页至少有一行可见内容（过程组头），保持一次点击一页。
5. **切进简洁档也按同一份预算自动连翻**：当前页全是过程块时，不能要求读者先点一次「加载更早」才发现页面是空的。预算与手动点击共用，翻到上限后停下，把决定权交回读者。
6. **“只有过程内容”分两句话**：还有更早页时只说「这一页只有过程内容」并留「加载更早」；游标为空才说「这段会话只有过程内容」。“看不见更早的页”不等于“它不存在”。
7. **档位与展开状态只活在当前这条会话的详情里**：切条目用 `key={entry.id}` 重挂载后回到默认；不跨会话记住，也不写进配置。它是阅读当下的姿势，不是全局偏好。
8. **过程组的键取组后那条对话块**（没有对话块就 `after:end`）：更早一页只会往组头添过程块，组的结束边界不变，读者已经点开的组不会因为 prepend 合并而收回。

## 边界

- **不做全局默认档配置**：档位是单条会话的阅读姿势；三只可调项仍只服务附件与维护（ADR-0037）。
- **不做“搜索/过滤过程块”第二条路**：四档已经覆盖“看多少过程”的需求；再加筛选就是第二套状态与第二套空态。
- **不改块投影与分页契约**：四档只影响客户端渲染；`/detail` 的块形状、游标与单块载荷闸不动（ADR-0026）。
- **会话信息直显与 sticky 标题**是这次界面改版的另一组决定，判据住 `docs/ui-spec.md` ⑥，不在这篇重复。

## 后果

- `src/client/trash-detail.tsx` 多出 `ViewMode`；`src/client/detail-blocks.ts` 承担 `threadItems` 的连续过程分组；`src/client/use-detail-pager.ts` 承担 `AUTO_OLDER_PAGE_LIMIT`、自动连翻与 prepend 后的滚动锚点；`src/client/ui/layout.css` 承担分段控件的伪类与焦点环。
- 旧的「全部展开 / 全部折叠」详情按钮与两条 copy key 删除；简洁档新增“这段会话只有过程内容”与“这一页只有过程内容”两句。
- 新控件必须自己描键盘焦点（这一代宿主的焦点环 token 是 transparent），并保持分段按钮的 `aria-pressed` 与工具栏可读性。
- 触发后自动继续翻页的上限住 `AUTO_OLDER_PAGE_LIMIT`（触发那一页不计入）；到达上限后页面仍停留、仍可手动继续。

## 被否掉的替代

- **保留「全部展开 / 全部折叠」一颗开关**：单块长短好解决，一页里过程块的数量解决不了；长会话仍要在几十条折叠头里逐条点。
- **只做简洁 / 详细两档**：少了“标准”这个默认姿势，读者要么全看要么全不看；四档是宿主已经教育过的语义。
- **简洁档不自动连翻，只提示“这一页没有对话”**：读者点一次仍然看不到东西，提示只是在解释失败。
- **简洁档无上限自动翻到底**：一次点击可能变成几十个串行请求，巨型工具会话会把面板拖住；上限 + 手动继续保留了决定权。
- **用原生 `<select>` 选档**：与插件其余控件不是一套长相；分段控件在窄栏也能一眼看全四档。
- **档位跨会话记住 / 进配置**：一条会话的阅读姿势不该变成另一条的默认，也不该进持久化面。
