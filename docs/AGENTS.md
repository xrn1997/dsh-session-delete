# 文档规范

本文件回答「这条内容该放哪、什么时候更新、什么时候归档」。它不重复业务规则：某条语义归谁见 `docs/architecture.md` §4，ADR 怎么写见 `docs/adr/ADR-FORMAT.md`。

**一条事实只住一个家**：当前事实源只写现在时；历史与变更过程只进 ADR 或 git；别处只链接，不复述。

## 1. 分层与职责

| 层 | 文档 | 只负责 | 不负责 | 事实源 |
| --- | --- | --- | --- | --- |
| 常驻规则 | `AGENTS.md` | 每次会话必须可见的硬约束、先读表、门 | 架构细节、构建步骤、历史 | 是（仅规则） |
| 用户入口 | `README.md` | 是什么、怎么装/用、数据在哪、兼容性（从 `package.json` 投影） | 维护者流程、裁决 | 是（用户可见事实；兼容性除外） |
| 领域词汇 | `CONTEXT.md` | 术语、语义、`_Avoid_` | 实现步骤、裁决理由 | 是（词汇） |
| 当前架构 | `docs/architecture.md` | 分层、依赖方向、主人清单、不变量、结构上的为什么 | 难逆裁决与被否方案（→ ADR）、操作步骤、历史 | 是 |
| 开发手册 | `docs/developing.md` | 构建、调试、门、真机验证、发版、环境坑 | 架构理由、用户用法 | 是（操作） |
| 贡献指南 | `CONTRIBUTING.md` | 提交信息、PR/Issue 约定、提交前门、发版边界 | 构建细节、架构理由 | 是（流程） |
| 发布历史 | `CHANGELOG.md` | 每个已发布版本的用户可见变化与升级注意 | 版本判据、逐提交明细 | 是（发布记录） |
| 界面规格 | `docs/ui-spec.md` | 现行状态、布局、层级、危险层级 | 像素/断点/文案键（在代码与测试）、历史 | 是（界面） |
| 决策记录 | `docs/adr/` | 一个决定的 why、边界、被否方案、后果 | 当前架构复述、计划、验收清单 | 是（why） |
| Agent 技能配置 | `docs/agents/*` | issue、标签、领域文档的 agent 约定 | 本仓事实源 | 否 |
| 生成快照 | `.qoder/repowiki/` | 工具生成的知识快照 | 手工维护、架构判断依据 | 否 |
| 本机过程工件 | `.superpowers/`、`.task-scratch/` | 任务简报、报告、审查草稿、采样脚本 | 入库、作为事实源 | 否 |
| 活跃工单 | GitHub Issues | 进行中的任务与验收 | 长期事实、裁决 | 否 |

## 2. 放置判据

- 每次会话看不到就会做错 → `AGENTS.md`。
- 用户装、用、数据在哪 → `README.md`。
- 词义 → `CONTEXT.md`。
- 当前结构、归属、不变量 → `docs/architecture.md`。
- 怎么构建、怎么验、怎么发版 → `docs/developing.md`。
- 怎么提交、PR、发版边界 → `CONTRIBUTING.md`。
- 每个版本改了什么、升级注意什么 → `CHANGELOG.md`。
- 界面现在长什么样 → `docs/ui-spec.md`。
- 为什么这么定、否掉了什么 → `docs/adr/`。
- 进行中的计划、调研、评审 → GitHub Issues 或本机 `.superpowers/`；完成后把长期成立的部分提炼进上面的事实源，其余随分支消失。
- 拿不准时按「读者在什么场景会打开它」选层。

## 3. 写作规则

1. 当前事实源只写现在时；历史、变更过程、旧方案只进 ADR 或 git。
2. 一条事实只有一个家；别处只链接。`docs/architecture.md` §4 是语义归属的唯一清单。
3. 代码与测试是最终真相；文档与代码冲突时改文档。
4. 引用仓内路径用相对路径，不写本机绝对路径；点名的路径必须真实存在，文档门会扫。
5. 不抄会腐烂的读数与计数；需要证据就指测试或代码。
6. ADR 只回答 why，不写现状地图；写作与翻案按 `docs/adr/ADR-FORMAT.md`。
7. `.qoder/repowiki/` 是生成快照，不手改、不作架构判断依据，也不把它的结论抄进手写文档；它的基线位置与重生成坑见 `docs/developing.md` 的「已知的环境坑」。
8. `docs/agents/*` 是 agent 技能配置，不是本仓事实源；本仓是单上下文，术语只查仓根 `CONTEXT.md`。

## 4. 生命周期

- **ADR**：编号追加、不复用；整篇翻案标 `superseded` 并指向接手的篇号；单条翻案就地订正并写日期。现状以代码与 `docs/architecture.md` 为准。
- **当前事实源**（`docs/architecture.md`、`docs/ui-spec.md`、`CONTEXT.md`、`docs/developing.md`）：语义、界面、词或操作变化时同批更新；不写历史。像素、断点、文案键的唯一定义在 `src/client/` 与 `tests/client/`。
- **README**：用户可见事实变化时更新；兼容性窗口与真机名单的事实源是 `package.json`，README 与徽章是投影，文档门校验。
- **CONTRIBUTING**：提交信息、PR/Issue 约定、提交前门或发版边界变化时同批更新；构建步骤仍住 `docs/developing.md`。
- **CHANGELOG**：只在发版时追加已发布版本；写用户可见变化与升级注意，未发布改动不预写；逐提交明细留 git。
- **过程工件**：仓库不建 plans/specs/archive。进行中的计划住 GitHub Issues 或本机 `.superpowers/`；完成后只把长期成立的部分提炼进事实源，其余不落库。需要保留历史理由时写 ADR。
- **生成快照**：整棵树重新生成，不逐文件修；与代码冲突时以代码为准。

## 5. 评审清单

文档改动提交前自查：

- 这条事实的家是否唯一？别处是否还有旧副本？
- 当前事实源里是否混进了历史、计划或「已改为」的口吻？
- 改动的路径、相对链接/锚点、ADR 编号、`§N` 指路是否都还活着？（`pnpm test` 的文档门）
- 发版前是否在 `CHANGELOG.md` 写清这一版的变化与升级注意？
- 根 `AGENTS.md` 是否仍在字节预算内？（数值与判据住 `tests/docs.test.ts`）
- 过程工件是否留在本机、没有入库？
- 生成的 `.qoder/repowiki/` 是否没有被手改？
