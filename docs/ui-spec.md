# 界面规格（现行）

结构与层级以本文为准；像素值、断点、文案键的唯一定义在 `src/client/` 与 `tests/client/`，本文不抄读数。历史取舍在 git 与 `docs/adr/`，这里只写现在长什么样。架构形状与主人清单见 `docs/architecture.md`。

## 1. 入口与面板

- 会话行菜单固定为「…归档 → 多选 → 删除」；删除是红色。会话在跑时删除置灰：0.2.2+ 的数据动作没有 `disabledReason`，行名改显示「删除（运行中）」；≤0.2.1 的 legacy 行仍用 tooltip 说明先停止。
- 删除的是**当前主视图**里的会话时，主视图随删除关闭（与宿主归档的 `clearArchivedCurrent` 同法）；撤销恢复成功后重新打开它。宿主客户端的常驻 `Session` 把 `removed` 记成粘性状态，`api-session/added` 不清它——不关就会停在「会话不可用」（判据与收尾住 `src/client/main-view.ts`，裁决见 ADR-0008）。
- 回收站入口是一对座位：`sidebar.panellist` 的一行 + `main` 同 key 的中央面板，必须同批注册（`selectPanel` 对未注册的 id 直接抛）。面板行常驻，不做计数角标；头部只放标题与条数/共可释放量（多选态那一行改说「已选 N 条」，合计让位给勾选数）；面板体顶端那排是视图开关（全部折叠/展开、多选），危险动作只有页脚那一排（见下文「危险层级」）。

## 2. 六个基础状态

| 状态 | 内容 | 规则 |
| --- | --- | --- |
| ① 会话行菜单 | 红色「删除」；顺序为归档 → 多选 → 删除 | 运行中置灰；0.2.2+ 显示「删除（运行中）」，≤0.2.1 用 tooltip 说明先停止 |
| ② 删除确认 | 可恢复说明；盘上有后代时先说「含 N 个子会话，将一起移入回收站」 | 主按钮 `primary`；N 读不到就不出这句、不写 0，也不因此禁用主按钮 |
| ③ 撤销提示 | 删除后即时出现 | 停留时长住 `undo-notices.ts` 的 `UNDO_HOLD_MS`；撤销即恢复；撤销在飞时动作按灰、连点只发一次，而且**横幅不自动熄灭**（timer 与淡出一起暂停，失败原文要落回这一条）；批量撤销失败不止一条时，横幅报失败条数与去重原因，只失败一条（或单条通知）时原文上屏；面板里恢复或彻底删除某个条目后，指向它（单条）或它所在那批（批量）的提示收掉，清空回收站成功后整条一并收掉——留着就是一条落点已经没了的假动作 |
| ④ 回收站清单 | 按项目分组的卡片；每条两行（标题 / 删除于… · 大小）；组视图另挂「含 N 个子会话」与「盘上还剩 M 个子会话」，两者不互相冒充；工作区已删的条目另挂「原工作区已不存在，恢复后归入未分组」 | 行右：恢复（描边）/ 彻底删除（安静红）；整行 `role=row`、内容与动作各住一格 `gridcell`（点行选中/看详情，点按钮动作；多选态勾选框占内容前的一格、动作列退场；按钮与勾选框住在格子里，对 AT 可达）；组头行也是 `row`，唯一一格横跨整行（列数与条目行一致）；头部条数与共可释放量（与彻底删除确认同一口径）；页脚「清空回收站…」 |
| ⑤ 彻底删除确认 | 单条与清空共用；单条报本次释放量 = 父 + 折进来的孩子 + 盘上后代 | 主按钮实心红；清空先对账再清 |
| ⑥ 单条详情 | 标题行（清册标题优先）+ 元信息表（时间、体量、计数、模型、位置——项目名取日志 header 的无损 `cwd`；删除于相对（绝对）合并一句；注入条数也在这张表里）+ 子会话段（段标题给已列条数与这些孩子的清册大小合计；确有折进这一行的孩子时逐条列标题/大小/删除时间，可点——大小与清单行同一格清册 `sizeBytes`；超过条数上限只列前若干条并另标总数（上限住 `src/trash/detail.ts` 的 `SUBAGENT_SUMMARY_LIMIT`））+ 正文块（用户原话、助手 Markdown、思考、工具调用/结果、注入上下文、系统消息、压缩摘要；附件跟着块走：图片内联、可点开放大，普通文件给下载 chip） | 助手文字与思考走 Markdown，用户提问保持原话；思考/工具/注入/系统/压缩默认折叠，折叠头给标签 + 首行摘要（工具另给成功/失败/未完成）；可逐块开合或「全部展开/全部折叠」；长会话按页加载更早，单块超上限标「已截断」；更早一页读失败只在「加载更早」旁内联原文，正文仍是「有内容」，不另立第五态；图片加载失败显示占位（名字与体量仍在；普通文件走 `<a download>`，没有页面内失败面——失败时浏览器可能把错误响应存成文件），附件不计入单块载荷闸；四态：未选中/读数中/失败/有内容。子会话段点一条，详情切到该孩子（同一套元信息+正文+分页），「← 返回父会话」回清单选中那条的详情（宽窄两档都画、与「返回清单」互斥，两颗共用同一个位置：标题那一排的**右端**，标题在前吃满余宽——按钮摆在标题之前会把整条标题的起点往右挤；同一件事不换角落，标题悬停给全称、热区不铺满整行；标题排的行高恒定，不随返回键有无而变——宽档父详情没有返回键，父子切换时下方元信息不跳行）；「子会话」段只在详情主体是清单选中那条时画（孩子视图里不画；单级的判据与为什么住 ADR-0029）；孩子视图离清单单级：清单选中与组动作（恢复/彻底删除按整组）不变，清单选中一变即收掉（点行或键盘选中）；返回/Esc 的两程次序住下文「键盘」一节；清单读不到那一拍详情整栏退场（走「清单为空或失败时不分栏」那一条，孩子也不例外），控制器不清孩子视图与选中——重读回来主体仍是那个孩子，「看不见≠没有」与选中行同一原则；清单换版把选中父行收走时孩子视图一并清场（ADR-0029） |

各张确认框（单删 / 批量删除 / 回收站恢复与彻底删除 / 孤儿会话清理 / 孤儿附件清理）共用同一条关框规则：**写入在飞时，取消、右上角关闭、遮罩与 Esc 一律拦住**——框先消失而写还在跑，用户会以为「没动」。规则住 `src/client/confirm-close.ts`。

## 3. 面板与清单

- 面板四态：读数中、空、读数失败、有条目。空态不出现「清空回收站…」；失败原文上屏 + 重试，不折成空态；**清空失败同样落「读数失败」这一格，失败期间旧行不再可操作（页脚动作不出现）**；已打开的回收站确认框（恢复 / 彻底删除 / 清空）随之收起（写入在飞时先留着，这一趟结束后再收）；**上一趟的附件提示一并收起**——清空可能删到一半才失败，没拿到回执就不能断言附件清没清；不做「刷新」按钮，读清单先对账。
- 两档形态：中央列够宽**且**清单有条目时走左右两栏（清单可拖、详情吃余下、正文自己限宽）；窄于此走下钻（清单铺满，点行详情铺满 + 返回）。宽档首读完成后自动选中第一条；窄档不自动下钻。清单为空或失败时不分栏。断点定值与列宽夹值以 `trash-panel.tsx` 的 `SPLIT_MIN_WIDTH` 和 `usePanelWidth` / `use-column-resize` 为准。
- 清单开关：组折叠、全部折叠/展开、多选；多选态「退出多选」永远可点（清单被清空或读失败后仍有出口）；折叠的条目不进 DOM；组头三态勾选框覆盖整组（含折叠起来的）。视图状态（折叠集、拖出的宽度）不跨会话记住。
- 键盘：`grid`/`row`/`gridcell`（组是带名字的 `rowgroup`；有行时容器才挂 `grid` 与它的 aria——为什么不是 `listbox` 见 ADR-0028），清单容器带 `aria-activedescendant`（只在选中行还在 DOM 里时指它），行用 roving tabindex——有行时恰好一行拿 `tabIndex=0`（选中行可见时是它，否则第一条可见行）；↑↓ 只走可见行、到端回卷，Enter/Space 说的是行（grid 的行级分工，不进格子），窄档 Enter/Space 下钻，宽档 Enter/Space 只选中，Esc 退下钻分两程：孩子视图开着先回父详情、再按一次才退（确认框或菜单开着时先归它；**焦点在回收站面板外时不归清单**——不在别处抢 Esc、也不把焦点拽回来；焦点在页面空地时仍按清单处理）；多选态 `aria-multiselectable`，Enter/Space 切换勾选；行内按钮 / 勾选框的 Enter/Space 归控件自己；详情不加 `aria-live`。
- 危险层级：页面本体唯一那块实心红**永远在页脚那一排的最后一颗**（非多选 =「清空回收站…」，多选 =「彻底删除 N 条」；写法是 `trash-view.ts` 的 `BULK_DANGER`）；行内那颗「彻底删除…」是安静的红（不铺底）；「恢复」描边；浮层确认用实心红。
- 失败落点：清单读失败只在清单块；某条正文读失败只在详情块，不冻结动作；操作失败原文落在出事那一行/那一块。附件清理失败或跳过不进清单或详情，在面板顶部出一条 notice（成功且没有附件读数时不出）。
- 失败块标 `role=status`；但插入即播报并不保证（`aria-live` 监听的是已在场区域的变更），尚未经 AT 验证，属已知边界。

## 4. 批量删除四态

宿主会话列表「⋯ → 多选」的显式模式、批量确认框、批量撤销横幅、部分失败态（框不关、原文落行、可重试）。两套与单删并存；结构以 `src/client/batch-bar.tsx`、`src/client/batch-confirm.tsx`、`src/client/batch-select.tsx`、`src/client/batch-selection-store.ts`、`src/client/host-rows.ts`、`src/client/batch-pick.ts` 为准。

## 5. 插件设置页的维护卡

挂点：宿主插件详情页的 `plugins.bundle.config` 槽位（按 bundle 包名寻址的 keyed 子槽位，位于描述与组件行之间；宿主页面声明它之后才出现，更早的宿主没有这张卡）。这一格只出现在插件详情页（视图契约与 `summary` 守卫见 ADR-0021）。卡里两段——**孤儿会话**与**孤儿附件**——各自独立：两段的忙碌、报告与失败互不影响。

- **段头**：标题、一句说明、状态、右侧一颗「检查」。一段的失败只落在它自己那段，另一段的状态不变。
- **状态行**（固定优先级）：`清理中…` → `检查中…` → `检查失败` → `尚未检查` → `没有发现` → `N 个`。失败时不许退回「尚未检查」——"没能回答"不是"还没问"。
- **孤儿会话**：检查只读 `/orphans`；报告 >0 时出警告条（数量 + 体积 + 失踪的父会话数）与「查看并清理」；确认框按项目列数量/体积，说明父已不存在、不可恢复、只清会话目录与会话独占的图片副本（投影缓存与共享图片不在内）；失败块原位摆原文 +「重试」；「已经不在」是中性提示，不计失败。清理走 `/apply` 的 `orphan-clean`，清完自动重查；这一趟顺带清掉的附件读数单独一行。
- **孤儿附件**：检查只读 `/attachment-orphans`；报告 >0 时出横幅（数量 · 体积）与「查看并清理」。点开先列图片缩略图（可点开放大；放大框可「另存为」；关闭不删任何东西；清单预览条数可配（见 `src/config.ts` / ADR-0037），超出时明说清理会处理全部），底部才是「清理这些附件」；正文说明只清 `.dsh` 内无引用的图片副本、源文件不受影响、共享引用保留。失败原位摆原文 +「重试」；清理走 `/attachment-clean`，清完自动重查。上一趟的回执（已清 / 跳过 / 逐文件失败）单独一行，不冒充检查状态。
- **手动触发**：挂载不发请求，没有自动检查、没有定时器；只有用户点「检查 / 查看并清理 / 清理」才发请求。0 条时只显示「没有发现」，不出现空动作。
- **危险层级**：卡片本体没有实心红；两段的确认框主按钮用实心红（与「清空回收站…」同一条规矩）。
- **回收站面板没有孤儿块**：本文 §3 的清单块里不再有残留警告条、失败块或清理确认框，面板也不会自动扫 `/orphans`。面板顶部只保留自己的**附件清理 warning**（purge / 清空的回执；成功且没有附件读数时不出）。
