# 界面规格（现行）

结构与层级以本文为准；像素值、断点、文案键的唯一定义在 `src/client/` 与 `tests/client/`，本文不抄读数。历史取舍在 git 与 `docs/adr/`，这里只写现在长什么样。架构形状与主人清单见 `docs/architecture.md`。

## 1. 入口与面板

- 会话行菜单固定为「…归档 → 多选 → 删除」；删除是红色。会话在跑时删除置灰：0.2.2+ 的数据动作没有 `disabledReason`，行名改显示「删除（运行中）」；≤0.2.1 的 legacy 行仍用 tooltip 说明先停止。
- 删除的是**当前主视图**里的会话时，主视图随删除关闭（与宿主归档的 `clearArchivedCurrent` 同法）；撤销恢复成功后重新打开它。宿主客户端的常驻 `Session` 把 `removed` 记成粘性状态，`api-session/added` 不清它——不关就会停在「会话不可用」（判据与收尾住 `src/client/main-view.ts`，裁决见 ADR-0008）。
- 回收站入口是一对座位：`sidebar.panellist` 的一行 + `main` 同 key 的中央面板，必须同批注册（`selectPanel` 对未注册的 id 直接抛）。面板行常驻，不做计数角标；头部只放标题与条数/共可释放量（多选态那一行改说「已选 N 条」，合计让位给勾选数）；面板体顶端那排是视图开关（全部折叠/展开、多选），危险动作只有页脚那一排（见下文「危险层级」）。

## 2. 六个基础状态

| 状态 | 内容 | 规则 |
| --- | --- | --- |
| ① 会话行菜单 | 红色「删除」；顺序为归档 → 多选 → 删除 | 运行中置灰；0.2.2+ 显示「删除（运行中）」，≤0.2.1 用 tooltip 说明先停止 |
| ② 删除确认 | 可恢复说明；盘上有后代时先说「含 N 个子会话，将一起移入回收站」 | 主按钮 `primary`；N 读不到就不出这句、不写 0，也不因此禁用主按钮 |
| ③ 撤销提示 | 删除后即时出现 | 停留时长住 `undo-notices.ts` 的 `UNDO_HOLD_MS`；撤销即恢复；撤销在飞时动作按灰、连点只发一次，而且**横幅不自动熄灭**（timer 与淡出一起暂停，失败原文要落回这一条）；批量撤销失败不止一条时，横幅报失败条数与去重原因，只失败一条（或单条通知）时原文上屏；面板里恢复或彻底删除某个条目后，指向它（单条）或它所在那批（批量）的提示收掉；清空回收站成功后，指向发起时在场条目的提示一并收掉（清空在飞期间新删除的提示不动）——留着就是一条落点已经没了的假动作 |
| ④ 回收站清单 | 按项目分组的**无边框行**（不铺底、不描边：一列带框的行叠起来就是"一叠卡片"，那是这一版要去掉的长相；圆角留着，悬停与选中的底色要靠它收边）；每条两行（标题 / 删除于… · 大小），次行取 `label-secondary` 而不是 tertiary，数字走 `tabular-nums`；组视图另挂「含 N 个子会话」与「盘上还剩 M 个子会话」，两者不互相冒充；**工作区已从宿主账本删掉的条目统一归入「未分组」组（该组永远沉底），行上不再挂去向提示**——分组本身就是去向的说明（`trash-view.ts` 的 `UNGROUPED_PROJECT_DIR`） | 行右两颗**图标按钮**：恢复（**本插件自绘**的回退箭头 ↩，风格对齐宿主图标——官方 `unarchive-outline` 与归档动作的"箱子"轮廓太近、`refresh-outline` 读作"刷新"；字形住 `src/client/ui/icons.tsx` 的 `IconRestoreOutlineRegular`）/ 彻底删除（垃圾桶）；常驻但默认低强调（tertiary 字色；强度分档住 `src/client/ui/layout.css` 的 `.sd-icon-btn`），鼠标经过、键盘落到这一行、或这一行被选中时提亮，**窄档常亮**——触屏没有 hover，点行即下钻，不能要求"先选中才出场"；多选态整排退场；键盘焦点有可见焦点环（住 `layout.css`）。整行 `role=row`、内容与动作各住一格 `gridcell`（点行选中/看详情，点按钮动作；多选态勾选框占内容前的一格、动作列退场；按钮与勾选框住在格子里，对 AT 可达）；组头行也是 `row`，唯一一格横跨整行（列数与条目行一致）；**组头开合指示学宿主工作区行**：默认显示官方文件夹图标（展开=开盖、收起=闭盒），鼠标经过时换成实心三角并旋转 90°（过渡时长住 `src/client/ui/layout.css` 的 `.sd-group-arrow`；`prefers-reduced-motion` 关闭过渡），触屏保持文件夹——条件住 `src/client/ui/layout.css`；头部条数与共可释放量（与彻底删除确认同一口径）；页脚「清空回收站…」 |
| ⑤ 彻底删除确认 | 单条与清空共用；单条报本次释放量 = 父 + 折进来的孩子 + 盘上后代 | 主按钮实心红；清空先对账再清 |
| ⑥ 单条详情 | 标题行（显示名次序：父行交来的子会话 label → 本条自己的 descriptor label / fork 子会话自己的日志标题（与工作中同名，ADR-0058）→ 清册标题 → 空串才回落日志 `session/title`；**整排 sticky**，长会话读到中段时返回仍钉在顶上——触屏没有 Esc 兜底）+ **会话信息一张表**（项目 → 模型 → 创建 → 最后活动 → 会话 id → 回收站目录 → 原本归档；项目名取日志 header 的无损 `cwd`，长串省略号收、全称走 `title`）+ **计量一行**（大小、活跃跨度、轮数、提问、助手消息、工具调用、注入上下文；活跃跨度是"量"不是时间点，归这一行）+ 子会话段（**默认收起**：段头是一条单行摘要条——品牌色分支图标 + 主色「子会话」+ **品牌色实心计数徽标**（孩子总数；超条数闸时仍给实数）+ 清册大小合计 + 展开 chevron；展开才逐条列标题（与标题行同一条显示名次序：父日志 catalog 的 label；没有 catalog 且标题撞父/兄弟的 fork 行用孩子自己日志的标题；清册标题回落）/大小/删除时间，可点——大小与清单行同一格清册 `sizeBytes`；组语义「随本条一起恢复或删除」住展开体；展开体**限高内滚**（上限住 `src/client/trash-detail.tsx`），条数再多也不撑爆正文；超过条数上限只列前若干条并在展开体另标总数（上限住 `src/trash/detail.ts` 的 `SUBAGENT_SUMMARY_LIMIT`）；**标题排另挂常驻计数徽标**，滚进正文后仍可见，点它展开并滚回该段）+ 正文块（用户原话、助手 Markdown、思考、工具调用/结果、注入上下文、系统消息、压缩摘要；附件跟着块走：图片内联、可点开放大，普通文件给下载 chip） | **会话信息全部直显、不折叠**（核对用的信息默认就该看得见；子会话**列表**是导航、默认收起，见上；「删除于」只在清单行，详情不重复）；子会话行是与清单行同语言的**无边框导航行**（分支图标 + primary 标题 + tertiary 大小/时间，**无 chevron**——chevron 只留给原地展开的折叠头；悬停底色住 `layout.css`）；助手文字与思考走 Markdown，用户提问保持原话；**工作步骤四档**（学宿主「工作步骤展示」；开关是详情工具栏右端的分段控件，默认「标准」）：<br>· **简洁**：只画用户提问＋助手回答，过程内容不出现；<br>· **标准**：对话照常，**连续的过程块收成一行（标签「工作步骤」+ 计数「N 步」）**，点开组后仍逐条折叠；<br>· **详细**：过程块逐条列出、各自折叠；<br>· **完全展开**：详细档 + 一次性把当前页所有过程块铺开（之后仍可逐条收起）。<br>折叠头给标签 + 首行摘要（工具另给成功/失败/未完成）；标签取 `label-secondary`、摘要留在 `label-tertiary`——两截同色只差一个字重时，真机上会糊成一句「系统消息You are an AI agent…」，标签就不像标签了；长会话按块分页，**有更早页时正文工具栏左端出「加载更早」**（点一次取一页；滚到顶不自动取数——ADR-0057）；**详情右缘常驻一道提问轨**——一句用户提问一格（只有附件、没有正文的提问不占格：页级附件闸可能让那种块整块不出线，一格跳不过去的刻度比没有更坏），悬停 / 键盘聚焦出预览（序号、时间、80 字预览、点它要不要先补页），点一下跳到那句：已加载的直接落位，未加载的按游标一页页补到它进窗再落位；落位只把那句对齐到标题排之下，**不画落地高亮框**（当前那句靠轨上那格与滚动位置认）；超过连翻上限只说「这句离现在太远，先点更近的一条」，不静默卡住；**简洁档的自动连翻照旧**——补回来的一页全是被隐藏的过程块时继续往前翻，直到出现对话内容、翻完或到达连翻上限（`AUTO_OLDER_PAGE_LIMIT`，住 `src/client/use-detail-pager.ts`），切到简洁档时当前页全是过程块也按同一上限自动连翻；到上限仍只有过程内容时只说「这一页只有过程内容」并留「加载更早」，游标为空才说「这段会话只有过程内容」；单块超上限标「已截断」；更早一页读失败把原文作为工具栏里的一格状态（`role="status"`，与按钮同一行；在飞时按钮禁用并改说「正在加载更早…」）上屏，正文仍是「有内容」，不另立第五态；图片加载失败显示占位（名字与体量仍在；普通文件走 `<a download>`，没有页面内失败面——失败时浏览器可能把错误响应存成文件），附件不计入单块载荷闸；四态：未选中/读数中/失败/有内容；**换到一条还没读过的条目时先保持上一条已就绪的详情**（标题、正文、滚动位置与右缘提问轨都还是上一条的；正文 `aria-busy` 且不可交互，提问轨跟着顶住但整条禁用，超过静默窗口才在标题排出「正在读这条会话…」），新详情到了整帧换掉、失败换该条的失败块——读数中的内容形状骨架只在**没有上一条可保持**时出现（首次）。子会话段点一条，详情切到该孩子（同一套信息+正文+分页），「← 返回父会话」回清单选中那条的详情（宽窄两档都画、与「返回清单」互斥，两颗共用同一个位置：标题那一排的**右端**，标题在前吃满余宽——按钮摆在标题之前会把整条标题的起点往右挤；同一件事不换角落，标题悬停给全称、热区不铺满整行；标题排的行高恒定，不随返回键有无而变——宽档父详情没有返回键，父子切换时下方信息不跳行）；「子会话」段只在详情主体是清单选中那条时画（孩子视图里不画；单级的判据与为什么住 ADR-0055 的「沿用」节）；孩子视图离清单单级：清单选中与组动作（恢复/彻底删除按整组）不变，清单选中一变即收掉（点行或键盘选中）；返回/Esc 的两程次序住下文「键盘」一节；清单读不到那一拍详情整栏退场（走「清单为空或失败时不分栏」那一条，孩子也不例外），控制器不清孩子视图与选中——重读回来主体仍是那个孩子，「看不见≠没有」与选中行同一原则；清单换版把选中父行收走时孩子视图一并清场（ADR-0055 的「沿用」节）；视图档位与展开状态只活在这一条会话的详情里，切条目重挂载后回到默认 |

各张确认框（单删 / 批量删除 / 回收站恢复与彻底删除 / 孤儿会话清理 / 孤儿附件清理）共用同一条关框规则：**写入在飞时，取消、右上角关闭、遮罩与 Esc 一律拦住**——框先消失而写还在跑，用户会以为「没动」。页脚（描边取消 / 主按钮确认 / 危险层级）共用 `src/client/confirm-dialog.tsx` 的 `ConfirmDialog`；关框规则本体住 `src/client/confirm-close.ts`。

## 3. 面板与清单

- 面板四态：读数中、空、读数失败、有条目。**挂载时先画上一趟的首帧快照**（清单、选中与详情一起续上），随后静默重读；重读成功换新、失败落「读数失败」并丢掉快照行（`unknown` 照旧不向下游交行）；刷新期间旧行仍可操作（写路径自己复核），清单容器带 `aria-busy`、不画「更新中」字样。空态不出现「清空回收站…」；失败原文上屏 + 重试，不折成空态；**清空失败同样落「读数失败」这一格，失败期间旧行不再可操作（页脚动作不出现）**；已打开的回收站确认框（恢复 / 彻底删除 / 清空）随之收起（写入在飞时先留着，这一趟结束后再收）；**上一趟的附件提示一并收起**——清空可能删到一半才失败，没拿到回执就不能断言附件清没清；不做「刷新」按钮，读清单先对账。
- 两档形态：中央列够宽**且**清单有条目时走左右两栏（清单可拖、详情吃余下、正文自己限宽）；窄于此走下钻（清单铺满，点行详情铺满 + 返回）。宽档首读完成后**在首帧绘制前**自动选中第一条（不露「未选中」一帧）；窄档不自动下钻。两栏都**无条件预留滚动条槽**（`scrollbar-gutter: stable`：滚动条出现/消失不改变正文宽度）；换到另一条详情时详情栏回到顶部。清单为空或失败时不分栏。断点定值与列宽夹值以 `trash-panel.tsx` 的 `SPLIT_MIN_WIDTH` 和 `usePanelWidth` / `use-column-resize` 为准。
- 清单开关：组折叠、全部折叠/展开、多选；多选态「退出多选」永远可点（清单被清空或读失败后仍有出口）；折叠的条目不进 DOM；组头三态勾选框覆盖整组（含折叠起来的）。视图状态（折叠集、拖出的宽度）不跨会话记住；**选中行与详情读数随首帧快照跨面板挂载保留**（ADR-0048），孩子视图仍在选中一变时收掉。
- 键盘：`grid`/`row`/`gridcell`（组是带名字的 `rowgroup`；有行时容器才挂 `grid` 与它的 aria——为什么不是 `listbox` 见 ADR-0028），清单容器带 `aria-activedescendant`（只在选中行还在 DOM 里时指它），行用 roving tabindex——有行时恰好一行拿 `tabIndex=0`（选中行可见时是它，否则第一条可见行）；↑↓ 只走可见行、到端回卷，Enter/Space 说的是行（grid 的行级分工，不进格子），窄档 Enter/Space 下钻，宽档 Enter/Space 只选中，Esc 退下钻分两程：孩子视图开着先回父详情、再按一次才退（确认框或菜单开着时先归它；**焦点在回收站面板外时不归清单**——不在别处抢 Esc、也不把焦点拽回来；焦点在页面空地时仍按清单处理）；多选态 `aria-multiselectable`，Enter/Space 切换勾选；行内按钮 / 勾选框的 Enter/Space 归控件自己；图标按钮与四档分段控件有可见键盘焦点环（住 `layout.css`）；详情不加 `aria-live`。
- 危险层级：页面本体唯一那块实心红**永远在页脚那一排的最后一颗**（非多选 =「清空回收站…」，多选 =「彻底删除 N 条」；写法是 `trash-view.ts` 的 `BULK_DANGER`）；行内那颗「彻底删除」是**图标按钮**（默认 tertiary 字色，不铺底、不描边，悬停时转红）；「恢复」同为图标按钮；浮层确认里只有**不可恢复**的动作（彻底删除、清空、孤儿清理）用实心红，单删与批量删除（移入回收站）及批量恢复仍是普通主按钮。
- 失败落点：清单读失败只在清单块；某条正文读失败只在详情块，不冻结动作；操作失败原文落在出事那一行/那一块。附件清理失败或跳过不进清单或详情，在面板顶部出一条 notice（成功且没有附件读数时不出）。
- 失败块标 `role=status`；但插入即播报并不保证（`aria-live` 监听的是已在场区域的变更），尚未经 AT 验证，属已知边界。

## 4. 批量删除四态

宿主会话列表「⋯ → 多选」的显式模式、批量确认框、批量撤销横幅、部分失败态（框不关、原文落行、可重试）。两套与单删并存；结构以 `src/client/batch-bar.tsx`、`src/client/batch-confirm.tsx`、`src/client/batch-select.tsx`、`src/client/batch-selection-store.ts`、`src/client/host-rows.ts`、`src/client/batch-pick.ts` 为准。

## 5. 插件设置页的卡片（可调项 + 维护）

挂点：宿主插件详情页的 `plugins.bundle.config` 槽位（按 bundle 包名寻址的 keyed 子槽位，位于描述与组件行之间；宿主页面声明它之后才出现，更早的宿主没有这张卡）。这一格只出现在插件详情页（视图契约与 `summary` 守卫见 ADR-0021），里面是**两张卡**：上面的「可调项」和下面的「维护」；占用者与先后以 `src/client/settings-cards.tsx` 为准，共用外壳以 `src/client/settings-view.ts` 为准。

### 5.1 可调项

- **三行数字输入**：孤儿附件预览条数（条）、附件单次响应上限（字节）、附件引用扫描的单 JSON 上限（字节）；标签 + 输入 + 单位一行，越界在那一行下面出「需为 min–max 的整数」。
- **读**：挂载读一次 `POST /config` 空体；`正在读当前值…` → 表单，或 `读取失败：原文` +「重试」。读不出来不摆空表单。
- **写**：只有「保存」会写；本地按 `CONFIG_LIMITS` 校验，没改动或越界时按钮禁用。写走同一段（带字段），成功状态「已保存；插件正在重启」，失败原文上屏。
- **重启语义**：写经宿主 `configEditor.edit`，Node 半这一行会重启；浏览器半的卡片不随卸载，用保存回执回填，重开插件页时重新读取。状态行不声称页面已经完成一次重新读取。
- 没有自动保存、没有定时器；读一次、用户点保存才写。

### 5.2 维护

卡里两段——**孤儿会话**与**孤儿附件**——各自独立：两段的忙碌、报告与失败互不影响。

- **段头**：标题、一句说明、状态、右侧一颗「检查」。一段的失败只落在它自己那段，另一段的状态不变。
- **状态行**（固定优先级）：`清理中…` → `检查中…` → `检查失败` → `尚未检查` → `没有发现` → `N 个`。失败时不许退回「尚未检查」——"没能回答"不是"还没问"。
- **孤儿会话**：检查只读 `/orphans`；报告 >0 时出警告条（数量 + 体积 + 失踪的父会话数）与「查看并清理」；确认框按项目列数量/体积，说明父已不存在、不可恢复、只清会话目录与会话独占的图片副本（投影缓存与共享图片不在内）；失败块原位摆原文 +「重试」；「已经不在」是中性提示，不计失败。清理走 `/apply` 的 `orphan-clean`，清完自动重查；这一趟顺带清掉的附件读数单独一行。
- **孤儿附件**：检查只读 `/attachment-orphans`；报告 >0 时出横幅（数量 · 体积）与「查看并清理」。点开先列图片缩略图（可点开放大；放大框可「另存为」；关闭不删任何东西；清单预览条数可配（见 `src/config.ts` / ADR-0037），超出时明说清理会处理全部），底部才是「清理这些附件」；正文说明只清 `.dsh` 内无引用的图片副本、源文件不受影响、共享引用保留。失败原位摆原文 +「重试」；清理走 `/attachment-clean`，清完自动重查。上一趟的回执（已清 / 跳过 / 逐文件失败）单独一行，不冒充检查状态。
- **手动触发**：维护两段挂载不发请求，没有自动检查、没有定时器；只有用户点「检查 / 查看并清理 / 清理」才发请求。0 条时只显示「没有发现」，不出现空动作。
- **危险层级**：两张卡本体都没有实心红；两段的确认框主按钮用实心红（与「清空回收站…」同一条规矩）。
- **回收站面板没有孤儿块**：本文 §3 的清单块里不再有残留警告条、失败块或清理确认框，面板也不会自动扫 `/orphans`。面板顶部只保留自己的**附件清理 warning**（purge / 清空的回执；成功且没有附件读数时不出）。
