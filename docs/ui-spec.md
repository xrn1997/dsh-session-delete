# 界面规格（现行）

结构与层级以本文为准；像素值、断点、文案键的唯一定义在 `src/client/` 与 `tests/client/`，本文不抄读数。历史取舍在 git 与 `docs/adr/`。架构形状与主人清单见 `docs/architecture.md`。

## 1. 入口与面板

- 会话行菜单固定为「…归档 → 多选 → 删除」（删除红色）；运行中的置灰与行名规则见本文 §2 ①。菜单只看本行状态；列表里看不见的子会话在跑，由 Node 半整组拒绝并回原文。
- 删除的是**当前主视图**里的会话时，主视图随删除关闭（与宿主归档同法）；撤销恢复成功后重新打开它。宿主客户端的常驻 `Session` 把 `removed` 记成粘性状态，不关就会停在「会话不可用」（收尾住 `src/client/main-view.ts`，裁决见 ADR-0008）。
- 回收站入口是一对座位：`sidebar.panellist` 的一行 + `main` 同 key 的中央面板。两条注册在同一张贡献表、同一个注册循环里，但**不是原子事务**；漏配一半由宿主 `selectPanel` 抛错暴露。面板行常驻，不做计数角标。
- 面板头部是平级分段「回收站 N | 归档 M」（无 H1；两档同尺寸；N/M 都是惰性读数），分段下那行是副标题：回收站档说条数与共可释放量，归档档说已归档数与合计（多选态改说「已选 N 条」）；面板体顶端是当前档的视图开关（全部折叠 / 展开、多选）。
- 危险层级（哪一颗是页面本体唯一的实心红、行内的动作为什么不是）住本文 §3。

## 2. 六个基础状态

| 状态 | 内容 | 规则 |
| --- | --- | --- |
| ① 会话行菜单 | 红色「删除」；顺序为归档 → 多选 → 删除 | 本行运行中置灰；0.2.2+ 显示「删除（运行中）」，≤0.2.1 用 tooltip 说明先停止 |
| ② 删除确认 | 可恢复说明；宿主语料里有后代时先说「含 N 个子会话，将一起移入回收站」 | 主按钮 `primary`；N 是语料读数、不是盘上目录数；读不到就不出这句、不写 0，也不因此禁用主按钮 |
| ③ 撤销提示 | 删除后即时出现，顶部居中 | 停留时长住 `src/client/undo-notices.ts` 的 `UNDO_HOLD_MS`；撤销即恢复；撤销在飞时动作按灰、连点只发一次，横幅不自动熄灭；撤销在飞期间横幅被新删除替换时，旧撤销的失败留到空档再上屏；批量失败报失败条数与去重原因；确认框始终压在横幅之上，开框时横幅只是公告；面板里恢复或彻底删除某条后收掉指向它的提示，清空成功后收掉发起时在场条目的提示 |
| ④ 回收站清单 | 按项目分组的**无边框行**；每条两行（标题 / 删除于… · 大小）；工作区已从宿主账本删掉的条目归入「未分组」组并沉底 | 行右两颗**图标按钮**：恢复（自绘回退箭头）/ 彻底删除（垃圾桶）；默认低强调，悬停、键盘落到该行或选中时提亮，**窄档常亮**；多选态整排退场；整行 `row`，内容与动作各一格 `gridcell`；组头行也是 `row`，唯一一格横跨整行；组头开合默认文件夹图标、悬停换实心三角并旋转，`prefers-reduced-motion` 关闭过渡，触屏保持文件夹；组头带条数；页脚「清空回收站…」 |
| ⑤ 彻底删除确认 | 单条、批量与清空共用页脚壳 | 单条报本次释放量 = 父 + 折进来的孩子 + 盘上后代，并说明被删会话自己的投影缓存记录会一并清；批量报条数；清空只报不可恢复、不报条数；主按钮实心红；清空先对账再清 |
| ⑥ 单条详情 | 标题行（显示名次序：父行交来的子会话 label → 本条自己的 descriptor label / fork 子会话自己的日志标题（ADR-0058）→ 清册标题 → 空串才回落日志 `session/title`；**整排 sticky**）+ **会话信息一张表**（项目 → 模型 → 创建 → 最后活动 → 会话 id → 回收站目录 → 原本归档）+ **计量一行**（大小、活跃跨度、轮数、提问、助手消息、工具调用、注入上下文）+ 子会话段（默认收起成单行摘要条：分支图标 + 主色「子会话」+ 实心计数徽标 + 清册大小合计 + 展开 chevron；展开才逐条列标题 / 大小 / 删除时间，可点；展开体限高内滚；超条数上限只列前若干条并另标总数；标题排另挂常驻计数徽标）+ 正文块（用户原话、助手 Markdown、思考、工具调用 / 结果、注入上下文、系统消息、压缩摘要；图片内联可放大，普通文件给下载 chip） | **会话信息全部直显、不折叠**；子会话**列表**是导航、默认收起；子会话行是与清单行同语言的无边框导航行（无 chevron）；助手文字与思考走 Markdown，用户提问保持原话；**工作步骤四档**：简洁（只画提问＋回答）/ 标准（连续过程块收成一行「工作步骤 · N 步」，点开仍逐条折叠）/ 详细（逐条列出、各自折叠）/ 完全展开（详细 + 铺开当前页）；折叠头给标签 + 首行摘要（工具另给成功 / 失败 / 未完成），标签与摘要分两档字色；长会话按块分页，**有更早页时工具栏左端出「加载更早」**（只由显式动作发起，滚到顶不自动取数，ADR-0057）；详情右缘**有提问时**出现提问轨（一句一格、悬停预览、点一下补页到那句、当前句跟滚动，不设开合）；简洁档的自动连翻照旧，到上限仍只有过程内容时只说「这一页只有过程内容」并留「加载更早」；单块超上限标「已截断」；更早一页读失败在工具栏同一行上屏，不另立状态 |

**详情状态是五支**：`idle` / `loading` / `holding` / `failed` / `ready`。`holding` 是换到还没读过的条目时先继续画上一条已就绪的详情（正文 `inert` + `aria-busy`，提问轨跟随但整条禁用），不是骨架、也不是「没有内容」；失败不丢上一条已就绪的详情。骨架只给首次打开。判据住 `src/client/use-detail-reader.ts` 的 `DetailState`。

各张确认框（单删 / 批量删除 / 回收站恢复与彻底删除 / 孤儿会话清理 / 孤儿附件清理 / 投影缓存清理）共用同一条关框规则：**写入在飞时，取消、右上角关闭、遮罩与 Esc 一律拦住**。页脚（描边取消 / 主按钮确认 / 危险层级）与关框规则共用 `src/client/confirm-dialog.tsx` 的 `ConfirmDialog`。

## 3. 面板与清单

- 面板四态：读数中、空、读数失败、有条目。**挂载时先画上一趟的首帧快照**（清单、选中与详情一起续上），随后静默重读；重读成功换新、失败落「读数失败」并丢掉快照行（`unknown` 不向下游交行）；刷新期间旧行仍可操作（写路径自己复核），容器带 `aria-busy`、不画「更新中」。空态不出现「清空回收站…」；失败原文上屏 + 重试，不折成空态；清空失败也落「读数失败」，旧行不再可操作、页脚动作不出现，已打开的面板确认框随之收起（写入在飞时先留着）；上一趟的附件提示一并收起。不做「刷新」按钮。
- 两档形态：中央列够宽**且**清单有条目时走左右两栏（清单可拖、详情吃余下、正文自己限宽）；窄于此走下钻。宽档首读完成后**在首帧绘制前**自动选中第一条；窄档不自动下钻。两栏都**无条件预留滚动条槽**；换到另一条详情时详情栏回到顶部。清单为空或失败时不分栏。断点定值与列宽夹值以 `src/client/trash-panel.tsx` 的 `SPLIT_MIN_WIDTH` 和 `usePanelWidth` / `use-column-resize` 为准。
- 清单开关：组折叠、全部折叠 / 展开、多选；多选态「退出多选」永远可点；折叠的条目不进 DOM；组头三态勾选框覆盖整组（含折叠起来的）。视图状态（折叠集、拖出的宽度）不跨会话记住；**选中行与详情读数随首帧快照跨面板挂载保留**（ADR-0048），孩子视图在选中一变时收掉。
- **两档共用一套 grid / 键盘契约**：`grid` / `row` / `gridcell`（组是带名字的 `rowgroup`；有行时容器才挂 `grid` 与它的 aria，为什么不是 `listbox` 见 ADR-0028）；容器带 `aria-activedescendant`（只在选中行还在 DOM 里时指它）；行用 roving tabindex（有行时恰好一行拿 `tabIndex=0`）；↑↓ 只走可见行、到端回卷；Enter / Space 说的是行：窄档下钻，宽档只选中；多选态 `aria-multiselectable`，Enter / Space 切换勾选。按键归属**按 key 判**：行内按钮 / 勾选框只拥有 Enter / Space，↑↓ 与其余键仍归清单；只有可编辑控件按自己的光标移动让路。图标按钮与四档分段控件有可见键盘焦点环；详情不加 `aria-live`。
- **Esc 分两程且只属于窄档下钻**：孩子视图开着先回父详情，再按一次才退下钻；确认框或菜单开着时先归它；**焦点在回收站面板外时不归清单**；宽档的孩子视图用「返回父会话」，不靠 Esc。顶层浮层名单与判据住 `src/client/ui/top-layer.ts`。
- **危险层级**：页面本体唯一那块实心红**永远在页脚那一排的最后一颗**（非多选 =「清空回收站…」，多选 =「彻底删除 N 条」）；行内「彻底删除」是图标按钮（默认 tertiary，悬停转红）；「恢复」同为图标按钮；浮层确认里只有**不可恢复**的动作（彻底删除、清空、孤儿清理）用实心红，单删、批量删除（移入回收站）与批量恢复仍是普通主按钮。
- 失败落点：清单读失败只在清单块；某条正文读失败只在详情块，不冻结动作；操作失败原文落在出事那一行 / 那一块。附件清理失败或跳过在面板顶部出一条 notice（成功且没有附件读数时不出）。失败块标 `role=status`；插入即播报并不保证，属已知边界。

### 3.1 归档档（平级分段）

- 面板头是平级分段 `回收站 N | 归档 M`；**M 是惰性读数**：首次成功读取前不显示，之后这一读失败仍保留上一次的成功读数。每次打开面板落回收站档；切档不持久化。
- 左列按项目分组，组内、组间按 `updatedAt` 倒序（最后活动，读不到时回退创建时间）；没有「未分组」组；组头与回收站同语言。行两条：显示名（label 非空优先，否则日志标题，都空回落「未命名 · <短 id>」）/ 元信息（最后活动或创建于 · 大小 · 子代理），行右两枚图标按钮（解除归档用官方 `unarchive-outline` 字形；删除用垃圾桶；均带 aria-label）。孤儿子会话照常显示并带「子代理」标签。行点击 = 选中看详情（多选态 = 切换勾选），不做原生打开。
- 宽档首读完成后自动选中第一条（同本文 §3）；归档详情右缘沿用同一条提问轨，信息表与计量行按归档投影画。
- 归档清单沿用本文 §3 的 grid / 键盘 / Esc 契约，但**只跟着当前档**：屏上没有那一档的下钻时，那一次 Esc 不归它收。行底色与 `aria-selected` 是两件事：底色说「详情正画着这一条」，多选态只把 `aria-selected` 让给勾选。
- 右栏两来源：两档各画各的详情投影。归档信息表**五行**（项目 / 日志末条 / 会话 id / 大小 / 状态：已归档主体「已归档」——含不在清单行里的已归档孩子视图；未归档孩子视图「随归档父会话查看」），无「回收站目录」「原本归档」。子会话段与回收站同一套呈现；父视图里孩子都可点开读正文（未归档孩子走已归档父会话的闭包只读校验）；孩子视图单级、不再开下一层且头部有返回父会话。标题与大小与主体配对，详情不重算。
- **两档尺寸口径分开**：归档行大小 = `sessionPersistence.sizeBytes`（宿主持久化日志工件字节，不含附件与子会话闭包；缺席显示「—」，合计只加已知，副标题追加「N 条大小缺席」）；回收站行大小 = 清册删除时的目录实测。**时间标签三分**：列表「最后活动」（有提问时间）/「创建于」（回退创建时间；都读不到则整格「时间未知」）、详情信息表「日志末条」。
- 归档档副标题 = `N 个已归档会话 · 合计 <已知字节>`，**不写「可释放」**（解除归档不释放字节）。
- 批量操作随档位：归档档页脚多选 =「解除所选」（无确认框、幂等）/「删除所选」（实心红；确认框语义同批量删除，删除进回收站、带撤销横幅）；回收站档页脚不变。整页唯一实心红仍在页脚那排最后一颗。
- 状态面：加载 / 行（含空表「没有已归档的会话」）/ 错误（原文上屏 + 重试）/ `corpus-missing`（「语料不可见」独立块 + 重试，不折成空态）。
- 归档档的清单 / 选中 / 详情**不进首帧快照**（`trash-snapshot` 是回收站的）；跨档切换双向清空勾选；折叠集按档独立。
- 新鲜度：宿主侧归档 / 解除归档经旁路观察实时反映（订阅不轮询）；观察不可用（服务缺席 / 形状不符）时安静降级为「打开归档档时重取 + 自己动作后重取」。

## 4. 批量删除四态

宿主会话列表「⋯ → 多选」的显式模式、批量确认框、批量撤销横幅、部分失败态（框不关、原文落行、可重试）。两套与单删并存；结构以 `src/client/batch-bar.tsx`、`src/client/batch-confirm.tsx`、`src/client/batch-select.tsx`、`src/client/batch-selection-store.ts`、`src/client/host-rows.ts`、`src/client/batch-pick.ts` 为准。

## 5. 插件设置页的卡片（可调项 + 维护）

挂点：宿主插件详情页的 `plugins.bundle.config` 槽位（按 bundle 包名寻址的 keyed 子槽位，位于描述与组件行之间；宿主页面声明它之后才出现，更早的宿主没有这张卡）。这一格只出现在插件详情页（视图契约与 `summary` 守卫见 ADR-0021），里面是**两张卡**：上面的「可调项」和下面的「维护」；占用者与先后以 `src/client/settings-cards.tsx` 为准，共用外壳以 `src/client/settings-view.ts` 为准。

### 5.1 可调项

- **三行数字输入**：孤儿附件预览条数（条）、附件单次响应上限（字节）、附件引用扫描的单 JSON 上限（字节）；标签 + 输入 + 单位一行，越界在那一行下面出「需为 min–max 的整数」。
- **读**：挂载读一次 `POST /config` 空体；`正在读当前值…` → 表单，或 `读取失败：原文` +「重试」。读不出来不摆空表单。
- **写**：只有「保存」会写；本地按 `CONFIG_LIMITS` 校验，没改动或越界时按钮禁用。写走同一段（带字段），成功状态「已保存；插件正在重启」，失败原文上屏。
- **重启语义**：写经宿主 `configEditor.edit`，Node 半这一行会重启；浏览器半的卡片不随卸载，用保存回执回填，重开插件页时重新读取。状态行不声称页面已经完成一次重新读取。
- 没有自动保存、没有定时器；读一次、用户点保存才写。

### 5.2 维护

卡里三段——**孤儿会话**、**孤儿附件**与**投影缓存**——各自独立：三段的忙碌、报告与失败互不影响。

- **段头**：标题、一句说明、状态、右侧一颗「检查」。一段的失败只落在它自己那段。
- **状态行**（固定优先级）：`清理中…` → `检查中…` → `检查失败` → `尚未检查` → `没有发现` → 计数（孤儿会话与孤儿附件说「N 个」，投影缓存说「N 条」）。失败时不许退回「尚未检查」——"没能回答"不是"还没问"。
- **孤儿会话**：检查只读 `/orphans`；报告 >0 时出警告条（数量 + 体积 + 失踪的父会话数）与「查看并清理」；确认框按项目列数量 / 体积，说明父已不存在、不可恢复、只清会话目录、会话独占的图片副本与这些会话自己的投影缓存记录（共享图片不在内）；失败块原位摆原文 +「重试」；「已经不在」是中性提示，不计失败。清理走 `/apply` 的 `orphan-clean`，清完自动重查；这一趟顺带清掉的附件读数单独一行。
- **孤儿附件**：检查只读 `/attachment-orphans`；报告 >0 时出横幅（数量 · 体积）与「查看并清理」。点开先列图片缩略图（可点开放大、可另存为；关闭不删任何东西；预览条数可配，超出时明说清理会处理全部），底部才是「清理这些附件」；正文说明只清 `.dsh` 内无引用的图片副本、源文件不受影响、共享引用保留。失败原位摆原文 +「重试」；清理走 `/attachment-clean`，清完自动重查。上一趟的回执（已清 / 跳过 / 逐文件失败）单独一行，不冒充检查状态。
