本模块是 `@xrn1997/dsh-session-delete` 插件的 npm 包根，不直接包含业务源码，而是通过 `package.json` 的 `exports` 暴露两个入口：Node 侧 `lib/index.js`（宿主服务端逻辑）与浏览器侧 `lib/client.js`（注入到 DSH 前端槽位的 React 控件）。构建由 `tsdown.config.ts` 驱动，产出两份独立 bundle：
- Node 半：ESM、target ES2024，`neverBundle @deepseek-ai/*`（依赖宿主提供的 Cordis/React），npm 依赖 inline。
- 浏览器半：CJS 单文件闭合工厂，通过 `banner/intro/footer` 包装成 `window.__ModuleLoader__.load({ id, factory })` 以适配 DSH 客户端加载协议；样式经自定义 tsdown 插件以 `<style>` 文本注入，而非走资产通道。

纯度门 (`gateClientImport`) 在构建期拒绝浏览器 bundle 中出现任何非平台白名单的 `require`（仅允许 `react` / `react/jsx-runtime` / `react-dom`），并拦截跨插件值 import；同时把 vfile 的 `#minpath` / `#minproc` / `#minurl` 分支请求重定向到 `.browser.js` 实现，避免 Node 内建泄漏进浏览器产物。

DSH 集成契约集中在两处：`package.json.dsh.bundle.patch = cordis.patch.yml` 声明对宿主的补丁位置，`dsh.client.inject` 列出需要注入的 locale 资源；`engines.dsh` 限定可安装版本区间，`dsh.compatibility.dshReleases` 记录桌面真机实测过的宿主代次。`pnpm-workspace.yaml` 放行 `@deepseek-ai/dsh-*` 的发布冷却闸并启用 esbuild 二进制构建脚本。类型声明由 `tsc -p tsconfig.build.json` 单独产出至 `lib/types/`，与 tsdown 的 JS 产物解耦。
