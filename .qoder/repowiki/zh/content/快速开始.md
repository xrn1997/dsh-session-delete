## 简介
本插件为 DeepSeek Harness（DSH）增加“删除会话”能力。官方提供归档，但没有删除；本插件把删除做成“移入回收站”，并保留显式的彻底删除入口。你可以随时恢复，也可以一次性清空回收站。

- 插件名：`@xrn1997/dsh-session-delete`
- 插件描述（来自本地化元数据）：“会话删除：删除 = 移入回收站（可恢复），另设显式的彻底删除。”
- 回收站本体留在本机，不联网、不上传。

## 安装与首次激活
最小步骤如下：

1. 确认 DSH 版本落在兼容区间，且 Node 版本满足要求。
2. 打开终端，执行安装命令：
   ```bash
   dsh plugin --profile <profile> add @xrn1997/dsh-session-delete
   ```
3. **重启 DSH 宿主**。插件的 Node 半不走热重载，必须重启才能注册路由、挂载回收站面板和会话行入口。
4. 激活成功后，你应该看到两个新入口：
   - 会话行「⋯」菜单中的「多选」与「删除」。
   - 侧栏面板列表中的「回收站」。

如果重启后仍然看不到入口，请继续看后面的“常见阻塞问题排查”。

卸载命令为：
```bash
dsh plugin --profile <profile> remove @xrn1997/dsh-session-delete
```
卸载只移除插件，不会自动清理 `~/.dsh/session-trash/` 下已经存在的回收站目录。

## 删除一个会话
1. 在 DSH 会话列表中，找到要删除的会话。
2. 点击该行右侧的「⋯」菜单。
3. 点击「删除」。
4. 在确认框中确认。确认框会提示这一组包含多少子会话，以及它们将一起移入回收站。
5. 删除完成后会出现一条撤销提示。在提示消失前点击「撤销」即可恢复。

重要规则：
- 删除按整组进行：父会话在磁盘上的子会话与更深后代会一起被移走。
- 如果该组中任一成员正在运行，整组会被拒绝，不会有任何副作用。
- 插件不会替用户终止正在进行的会话；请先手动停止，再删除。

## 在回收站面板查看结果
1. 打开 DSH 侧栏。
2. 找到「回收站」一行，点击进入。
3. 左侧列出按项目分组的会话；右侧显示选中会话的元信息与正文。
4. 正文只显示真实的人机对话内容，不会混入宿主注入的上下文与工具调用细节。
5. 页脚有唯一的一个红色按钮「清空回收站…」，用于显式彻底删除全部回收站条目。

回收站是“看得见正文再决定恢复不恢复”的地方。即使原工作区已被删除，你仍可在回收站里查看它。

## 恢复会话
1. 打开「回收站」面板。
2. 在左列选中要恢复的会话。
3. 点击该条目的「恢复」。
4. 会话会回到原来的项目目录，并按删除前的归档可见性还原。
5. 如果原工作区已被删除，会话仍会回盘，但会归入「未分组」。

批量恢复：
- 在回收站面板工具栏进入「多选」。
- 勾选多条后确认，系统逐条执行恢复。
- 失败不会连坐，失败的条目保留在清单中，可单独重试。

## 清空回收站
1. 打开「回收站」面板。
2. 点击页脚的「清空回收站…」按钮。
3. 二次确认后，系统先对回收站目录与清册做一遍对账，再执行彻底删除。
4. 认不出来的手工目录不会被误动，也不会出现在回收站清单中。

注意：
- “清空回收站”是显式动作，没有自动过期时间。
- 单条「彻底删除…」与「清空回收站…」共用同一个二次确认语义。
- 彻底删除不可撤销，使用前应确认不再需要恢复。

## 存储域 `xrn1997_session_delete_trash` 是什么
`xrn1997_session_delete_trash` 是本插件向 DSH 存储域服务注册的**回收站清单**所使用的域名。它的作用不是存放压缩后的会话日志，而是维护一份“哪些会话进了回收站”的可查询清单。

关键点：
- 名称以 `xrn1997_` 开头，避免与其他插件共享同一名空间。
- 域名只能使用小写字母、数字和下划线，因此不能用 npm 包名中的 `@` `/` `-`。
- 清单介质位于 `~/.dsh/storages/`，由宿主 storage domain facility 管理。
- 回收站本体实际文件位于 `~/.dsh/session-trash/`。
- 清单采用“每条记录独立布局”，坏记录会被备份跳过，不至于让整个域开不起来。
- 若清册丢失，只要回收站目录还在，插件仍可读取会话自描述信息重建事实；反之，清册也可能从目录扫描恢复。

简而言之：  
- `~/.dsh/session-trash/`：**回收站文件本体**  
- `xrn1997_session_delete_trash`：**回收站清单的存储域名**

## 关键认知：删除 = 移动，不是直接删盘
这是理解本插件最重要的一个判断：

- 普通删除不是立即从磁盘抹掉。
- 删除是把会话目录移动到 `~/.dsh/session-trash/<时间戳>-<原目录名>/`。
- 同时更新工作区账本、归档表与回收站清单。
- 因为可恢复，所以删除过程是可回滚的；而“彻底删除 / 清空回收站”才是不可逆的。
- 回收站与 `sessions/` 同卷时，移动靠原子 rename，速度很快。
- 附件不参与连带关系，不会因为删除会话而被自动回收。

这个认知能帮你回答很多现象：为什么刚删完还要刷新、为什么手工搬目录不算恢复、为什么“删除工作区”之后还能恢复。

## 常见阻塞问题排查
| 现象 | 原因 | 解决建议 |
|---|---|---|
| 安装成功但侧栏没有「回收站」，会话菜单也没有「删除」 | 取数通道探测不过时，插件不会注册任何入口；也可能是宿主尚未重启。 | 先重启宿主。若仍无入口，检查 DSH 版本是否落在兼容区间，并确认本次安装确实完成。 |
| 删完后侧栏那一行还在 | 插件只在宿主确实不再列出该会话时才通告客户端移除；刚巧遇到边界情况时宁可沉默。 | 刷新页面或等待重连；冷会话通常删完即走，活体会话可能暂时留在「未分组」。 |
| 正在运行的会话无法删除 | 活跃判据与官方归档准入同源；插件不会替用户杀掉进程。 | 先停止该会话及其子会话，再删除。报错信息会指出是哪个 id 仍在运行。 |
| 批量删除只成功了一部分 | 批量执行逐条进行，失败不连坐。 | 不要关确认框；失败行的原文会留在那里，点击「重试这 N 条」处理失败项。 |
| 把工作区目录删了，回收站里却找不到对应会话 | 宿主的“删除工作区”只删注册，保留目录和日志；这类会话属于“未分组”。 | 在回收站面板里点「恢复」，它会回盘并归入「未分组」。 |
| 手工把回收站目录搬回 `sessions/`，列表里没有 | 恢复不只是移动目录，还要挂账本、还原归档可见性。 | 不要在回收站目录里手工搬运；请在面板里点「恢复」。 |
| Node 版本过低导致无法安装 | 包声明要求 Node `>=24`。 | 升级 Node 后再安装，或使用离线 tarball 方式分发。 |
| 旧版 DSH 缺少菜单槽位 | 低于 `0.1.7-rc.2` 的版本可能缺失行首勾选槽位或会话行入口。 | 升级到兼容窗口内的 DSH 版本。 |

## 从零到可操作的最小步骤清单
1. 准备 DSH 宿主版本在 `>=0.1.7-rc.2 <0.3.0-0`，Node 版本 `>=24`。
2. 执行安装：`dsh plugin --profile <profile> add @xrn1997/dsh-session-delete`。
3. 重启 DSH 宿主。
4. 打开会话列表，找到一条非运行中的会话。
5. 点击「⋯」→「删除」→ 确认。
6. 打开侧栏「回收站」，确认该会话出现在回收站清单中。
7. 如需恢复，点击「恢复」；如需永久删除，点击「清空回收站…」。
8. 如果入口没出现，先重启宿主，再对照常见问题排查。

这套流程覆盖了“安装 → 激活 → 删除 → 查看 → 恢复 → 清空”的最小闭环，不要求你理解内部实现，只要求你能安全地用完一次。
